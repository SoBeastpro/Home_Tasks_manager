# Сервис учета домашних дел

Консольное приложение и начальный веб-интерфейс на Django для учета
домашних дел: хранит перечень дел, закрепляет их за членами семьи,
распределяет по категориям и отслеживает статусы и сроки выполнения.

## Назначение

Приложение решает задачу распределения бытовых обязанностей: позволяет
записывать домашние дела, назначать исполнителя, группировать дела по
категориям, менять статус выполнения, находить просроченные дела и
оценивать нагрузку участников.

Консольная версия (ПР3) дополнена веб-интерфейсом на Django (ПР5),
переведена на шаблоны Django (ПР6). На ПР7 данные были перенесены
в SQLite. На ПР9 веб-страницы получают данные через Django ORM.
На ПР10 добавлена административная панель Django.

## Целевая аудитория

- члены семьи, которые ведут общее хозяйство и делят бытовые обязанности;
- жильцы съемной квартиры, распределяющие дежурства между собой;
- отдельный пользователь, которому нужен простой список домашних задач.

## Предметная область

Предметная область — ведение домашнего хозяйства. Основные объекты:
пользователь, категория, статус и дело. Пользователь может выполнять
несколько дел, категория объединяет однотипные дела, статус описывает
текущее состояние. Дело связывает пользователя и категорию.

## Основные классы

### Entity — именованная сущность

Базовый класс для пользователя и категории. Отношение «является»:
пользователь и категория являются именованными сущностями.

Основные атрибуты:

- `id` — уникальный идентификатор;
- `name` — название.

Основные методы:

- `matches()` — проверка подстроки в названии;
- `__str__()` — строковое представление.

### User — пользователь

Объект `User` представляет члена семьи, отвечающего за дела.
Наследует `Entity`.

Основные атрибуты:

- `id`, `name` — идентификатор и имя;
- `email` — адрес электронной почты.

Основные методы:

- `validate_name()` — проверка имени (`@staticmethod`);
- `from_data()` — создание объекта из словаря JSON (`@classmethod`);
- `to_data()` — данные для сохранения в JSON;
- `__str__()` — строковое представление пользователя.

### Category — категория

Объект `Category` представляет группу однотипных дел.
Наследует `Entity`.

Основные атрибуты:

- `id` — уникальный идентификатор категории;
- `name` — название категории.

Основные методы:

- `validate_name()` — проверка названия (`@staticmethod`);
- `from_data()` — создание объекта из словаря JSON (`@classmethod`);
- `to_data()` — данные для сохранения в JSON;
- `__str__()` — строковое представление категории.

### Status — статус

Базовый класс статуса. Конкретные состояния реализованы наследниками
`PlannedStatus`, `InProgressStatus` и `DoneStatus`. Полиморфизм:
метод `is_done()` и строковое представление зависят от подкласса.

Основные методы:

- `is_done()` — признак завершения;
- `next_status()` — следующий статус жизненного цикла;
- `from_name()` — создание объекта статуса по названию (`@classmethod`);
- `__str__()` — название статуса.

### Chore — дело

Объект `Chore` представляет домашнюю задачу и связывает объекты
`User` и `Category`. Это композиция: дело содержит ссылки на связанные
объекты, а не только их идентификаторы.

Основные атрибуты:

- `id` — уникальный идентификатор дела;
- `title` — название;
- `user` — объект `User`;
- `category` — объект `Category`;
- `priority` — числовой приоритет;
- `due_date` — срок выполнения;
- `status` — объект `Status` (инкапсулирован, доступен через `@property`).

Основные методы:

- `validate_title()`, `validate_priority()` — проверки (`@staticmethod`);
- `is_done()`, `complete()`, `set_status()` — работа со статусом;
- `days_left()`, `deadline_message()`, `is_overdue()` — работа со сроком;
- `to_data()` — преобразование в данные JSON;
- `__str__()` — строковое представление дела.

## Взаимодействие объектов

```
Chore
├── user → User
├── category → Category
└── status → Status
```

Данные связанных объектов доступны через атрибуты дела:
`chore.user.name`, `chore.category.name`, `chore.status`.
При сохранении в JSON вместо объектов записываются идентификаторы
`user_id` и `category_id`. При загрузке выполняется обратное
преобразование: по идентификаторам находятся объекты `User` и
`Category`, после чего создаётся `Chore`.

## Возможности

- просмотр всех дел в виде таблицы с сортировкой по сроку выполнения;
- поиск дел по части названия;
- отбор дел по исполнителю, категории и дате;
- просмотр карточки дела с расчетом оставшихся дней и подсказкой о сроке;
- добавление, удаление дел и изменение их статуса;
- вывод просроченных дел;
- ведение справочников пользователей и категорий;
- статистика по статусам, категориям и нагрузке исполнителей.

## Страницы веб-интерфейса

Данные страниц загружаются из `db.sqlite3` через Django ORM.
Представления обращаются к моделям `User`, `Category` и `Chore`
и передают объекты в шаблоны через context.

- `/` — главная: описание приложения и навигация
  (view-функция `index()`);
- `/chores/` — список дел с поиском, фильтрами, сортировкой
  и пагинацией (`chore_list()`);
- `/chores/open/` — невыполненные дела (`exclude()`);
- `/chores/by-date/` — поиск дел по сроку (GET-форма);
- `/chores/<int:chore_id>/` — карточка дела
  (`get_object_or_404()`);
- `/categories/` — категории и число дел (`annotate()`);
- `/categories/<slug:slug>/` — категория и её дела
  (`get_absolute_url()`);
- `/admin/` — административная панель Django;
- `/categories/statistics/` — статистика: `Count`, `Avg`,
  `annotate()`, группировка.

Если дело или категория с указанным идентификатором не найдены,
страница возвращает код статуса 404. Несуществующий адрес
обрабатывает `handler404` → `page_not_found()`.

Страницы собираются шаблонами Django. Представления передают данные
через контекст и вызывают `render()`. Функция `page()` больше
не используется.

Ссылки формируются через `{% url %}` и пространства имён:
`homepage:index`, `chores:list`, `chores:open`, `chores:by_date`,
`chores:detail`, `categories:list`, `categories:detail`,
`categories:statistics`. Поиск и фильтры списка дел передаются
GET-параметрами `q`, `date`, `category`, `user`, `sort`, `page`.

## Django Template Language

Общий каркас страниц — `templates/base.html`. Дочерние шаблоны
подключают его через `{% extends "base.html" %}` и заполняют блоки
`title` и `content`. Навигация вынесена в
`templates/includes/navigation.html`.

Повторяющиеся фрагменты:

- `chores/includes/chore_card.html` — карточка дела;
- `chores/includes/chore_status.html` — статус дела;
- `categories/includes/category_card.html` — карточка категории.

Списки строятся циклом `{% for %}` с веткой `{% empty %}`.
Отсутствие объекта и статус дела отображаются через `{% if %}`.

Фильтры шаблонов:

- `{{ chores|length }}` — количество дел;
- `{{ chore.title|default:"Без названия" }}` — значение по умолчанию.

## Статические файлы

Статика лежит в `homepage/static/homepage/`:

- `css/style.css` — собственные стили;
- `js/main.js` — текущий год в подвале;

В шаблонах используется `{% load static %}` и `{% static %}`.

## Основные операции

### Используется в веб-интерфейсе (ПР5–ПР10)

- просмотр списка дел;
- просмотр карточки дела (исполнитель, категория, срок, статус);
- просмотр списка категорий;
- просмотр категории и связанных с ней дел;
- невыполненные дела и поиск дел по сроку;
- поиск, фильтрация, сортировка и постраничный вывод дел;
- статистика по категориям и статусам;
- данные веб-страниц загружаются через Django ORM;
- управление делами, категориями и пользователями через `/admin/`.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консоли. В вебе они
появятся после форм и POST-запросов:

- добавление, изменение и удаление дел;
- поиск дел по названию;
- отбор дел по исполнителю и категории;
- изменение статуса дела;
- ведение справочников пользователей и категорий.

## Хранение данных

Веб-интерфейс читает данные из `db.sqlite3` через Django ORM.
Файл `data/home_tasks.sqlite` — исходная база ПР7, она не меняется.
JSON-файлы остаются источником для консоли и импорта в базу ПР7.

Модель `User`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | AutoField | первичный ключ Django |
| `name` | CharField | имя пользователя |
| `email` | EmailField | электронная почта |

Модель `Category`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | AutoField | первичный ключ Django |
| `name` | CharField | название категории |
| `slug` | SlugField | латинский адрес страницы |

Модель `Chore`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | AutoField | первичный ключ Django |
| `title` | CharField | название дела |
| `user` | ForeignKey | исполнитель, `on_delete=PROTECT`, `related_name="chores"` |
| `category` | ForeignKey | категория, `on_delete=PROTECT`, `related_name="chores"` |
| `priority` | PositiveIntegerField | приоритет |
| `due_date` | DateField | срок выполнения |
| `status` | CharField / TextChoices | статус выполнения |
| `is_high_priority` | GeneratedField | высокий приоритет, если `priority >= 3` |

Таблицы Django создаются миграциями. Исходные данные ПР7
переносятся скриптом:

```
python manage.py migrate
python db/inspect_source_db.py
python db/import_sqlite_to_orm.py
```

Файл `db.sqlite3` в репозиторий не входит: после клонирования
нужно применить миграции и выполнить перенос.

SQL-слой ПР7 (`sql/schema.sql`, `sql/queries.sql`,
`db/database.py`) сохранён, представления его больше не используют.

Страницы, которые показывают данные ORM:

- `/chores/` — список дел;
- `/chores/open/` — невыполненные дела;
- `/chores/by-date/` — поиск по сроку;
- `/chores/<int:chore_id>/` — карточка дела;
- `/categories/` — категории и число дел;
- `/categories/<int:category_id>/` — категория и её дела;
- `/categories/statistics/` — статистика.

Даты в JSON и SQLite хранятся как `ГГГГ-ММ-ДД`. В консоли даты
вводятся и выводятся в формате `ДД.ММ.ГГГГ`.

`data/users.json`:

```json
[
  { "id": 1, "name": "Алексей", "email": "alexey@home.local" }
]
```

`data/categories.json`:

```json
[
  { "id": 1, "name": "Кухня" }
]
```

`data/chores.json`:

```json
[
  {
    "id": 1,
    "title": "Помыть посуду",
    "user_id": 1,
    "category_id": 1,
    "priority": 3,
    "due_date": "2026-09-18",
    "status": "Запланировано"
  }
]
```
