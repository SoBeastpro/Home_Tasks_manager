# Сервис учета домашних дел

Консольное приложение для учета домашних дел: хранит перечень дел,
закрепляет их за членами семьи, распределяет по категориям и отслеживает
статусы и сроки выполнения.

## Назначение

Приложение решает задачу распределения бытовых обязанностей: позволяет
записывать домашние дела, назначать исполнителя, группировать дела по
категориям, менять статус выполнения, находить просроченные дела и
оценивать нагрузку участников.

## Целевая аудитория

- члены семьи, которые ведут общее хозяйство и делят бытовые обязанности;
- жильцы съемной квартиры, распределяющие дежурства между собой;
- отдельный пользователь, которому нужен простой список домашних задач.

## Предметная область

Предметная область — ведение домашнего хозяйства. Домашнее дело описывается
названием, ответственным пользователем, категорией, приоритетом, сроком
выполнения и текущим статусом. В процессе работы дело переходит из
состояния «Запланировано» в «В работе», а затем в «Выполнено». Пользователю
важно видеть, какие дела просрочены, какие запланированы на конкретную дату
и как нагрузка распределена между исполнителями.

## Основные сущности

- **Пользователь** — член семьи, отвечающий за выполнение дел
  (идентификатор, имя);
- **Дело** — домашняя задача (идентификатор, название, исполнитель,
  категория, приоритет, срок выполнения, статус);
- **Категория** — группа однотипных дел: кухня, уборка, покупки, техника
  (идентификатор, название);
- **Статус** — состояние дела: «Запланировано», «В работе», «Выполнено».

## Возможности

- просмотр всех дел в виде таблицы с сортировкой по сроку выполнения;
- поиск дел по части названия;
- отбор дел по исполнителю, категории и дате;
- просмотр карточки дела с расчетом оставшихся дней и подсказкой о сроке;
- добавление, удаление дел и изменение их статуса;
- вывод просроченных дел;
- ведение справочников пользователей и категорий;
- статистика по статусам, категориям и нагрузке исполнителей.

## Формат хранения данных

Данные хранятся в JSON-файлах каталога `data/`. Пользователи и категории
после загрузки преобразуются в словари, ключом которых является
идентификатор; дела хранятся списком словарей. Даты записываются в формате
`ГГГГ-ММ-ДД`, а вводятся и выводятся в формате `ДД.ММ.ГГГГ`.

`data/users.json`:

```json
[
  { "id": 1, "name": "Алексей" }
]
```

`data/categories.json`:

```json
[
  { "id": 1, "name": "Кухня" }
]
```

`data/chores.json`:

```json
[
  {
    "id": 1,
    "title": "Помыть посуду",
    "user_id": 1,
    "category_id": 1,
    "priority": 3,
    "due_date": "2026-09-18",
    "status": "Запланировано"
  }
]
```

## Преемственность этапов

Начальный сценарий ПР1 сохранен в проекте: одиночные переменные
`chore_title`, `category_name`, `owner_name`, `due_date` и `is_done`
переработаны в структуры данных `chores`, `users` и `categories`, а функции
`get_chore_status()`, `get_days_left()`, `get_deadline_message()` и
`get_priority_label()` перенесены в модуль `chores.py` и используются при
выводе карточки дела вместе с новыми функциями проекта.
