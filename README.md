# Сервис учета домашних дел

Консольное приложение и начальный веб-интерфейс на Django для учета
домашних дел: хранит перечень дел, закрепляет их за членами семьи,
распределяет по категориям и отслеживает статусы и сроки выполнения.

## Назначение

Приложение решает задачу распределения бытовых обязанностей: позволяет
записывать домашние дела, назначать исполнителя, группировать дела по
категориям, менять статус выполнения, находить просроченные дела и
оценивать нагрузку участников.

## Целевая аудитория

- члены семьи, которые ведут общее хозяйство и делят бытовые обязанности;
- жильцы съемной квартиры, распределяющие дежурства между собой;
- отдельный пользователь, которому нужен простой список домашних задач.

## Предметная область

Предметная область — ведение домашнего хозяйства. Основные объекты:
пользователь, категория, статус и дело. Пользователь может выполнять
несколько дел, категория объединяет однотипные дела, статус описывает
текущее состояние. Дело связывает пользователя и категорию.

## Основные классы

### Entity — именованная сущность

Базовый класс для пользователя и категории. Отношение «является»:
пользователь и категория являются именованными сущностями.

Основные атрибуты:

- `id` — уникальный идентификатор;
- `name` — название.

Основные методы:

- `matches()` — проверка подстроки в названии;
- `__str__()` — строковое представление.

### User — пользователь

Объект `User` представляет члена семьи, отвечающего за дела.
Наследует `Entity`.

Основные атрибуты:

- `id`, `name` — идентификатор и имя;
- `email` — адрес электронной почты.

Основные методы:

- `validate_name()` — проверка имени (`@staticmethod`);
- `from_data()` — создание объекта из словаря JSON (`@classmethod`);
- `to_data()` — данные для сохранения в JSON;
- `__str__()` — строковое представление пользователя.

### Category — категория

Объект `Category` представляет группу однотипных дел.
Наследует `Entity`.

Основные атрибуты:

- `id` — уникальный идентификатор категории;
- `name` — название категории.

Основные методы:

- `validate_name()` — проверка названия (`@staticmethod`);
- `from_data()` — создание объекта из словаря JSON (`@classmethod`);
- `to_data()` — данные для сохранения в JSON;
- `__str__()` — строковое представление категории.

### Status — статус

Базовый класс статуса. Конкретные состояния реализованы наследниками
`PlannedStatus`, `InProgressStatus` и `DoneStatus`. Полиморфизм:
метод `is_done()` и строковое представление зависят от подкласса.

Основные методы:

- `is_done()` — признак завершения;
- `next_status()` — следующий статус жизненного цикла;
- `from_name()` — создание объекта статуса по названию (`@classmethod`);
- `__str__()` — название статуса.

### Chore — дело

Объект `Chore` представляет домашнюю задачу и связывает объекты
`User` и `Category`. Это композиция: дело содержит ссылки на связанные
объекты, а не только их идентификаторы.

Основные атрибуты:

- `id` — уникальный идентификатор дела;
- `title` — название;
- `user` — объект `User`;
- `category` — объект `Category`;
- `priority` — числовой приоритет;
- `due_date` — срок выполнения;
- `status` — объект `Status` (инкапсулирован, доступен через `@property`).

Основные методы:

- `validate_title()`, `validate_priority()` — проверки (`@staticmethod`);
- `is_done()`, `complete()`, `set_status()` — работа со статусом;
- `days_left()`, `deadline_message()`, `is_overdue()` — работа со сроком;
- `to_data()` — преобразование в данные JSON;
- `__str__()` — строковое представление дела.

## Взаимодействие объектов

```
Chore
├── user → User
├── category → Category
└── status → Status
```

Данные связанных объектов доступны через атрибуты дела:
`chore.user.name`, `chore.category.name`, `chore.status`.
При сохранении в JSON вместо объектов записываются идентификаторы
`user_id` и `category_id`. При загрузке выполняется обратное
преобразование: по идентификаторам находятся объекты `User` и
`Category`, после чего создаётся `Chore`.

## Возможности

- просмотр всех дел в виде таблицы с сортировкой по сроку выполнения;
- поиск дел по части названия;
- отбор дел по исполнителю, категории и дате;
- просмотр карточки дела с расчетом оставшихся дней и подсказкой о сроке;
- добавление, удаление дел и изменение их статуса;
- вывод просроченных дел;
- ведение справочников пользователей и категорий;
- статистика по статусам, категориям и нагрузке исполнителей.

## Назначение модулей

### `main.py`

Точка входа консоли: меню, ввод пользователя и вызов функций пакета
`models`. Не хранит данные предметной области в виде словарей.

### `models/`

Классы предметной области и функции работы с коллекциями объектов.

### `storage.py`

Загрузка и сохранение JSON: словари ↔ объекты `User`, `Category`, `Chore`.

### `utils.py`

Вспомогательные функции безопасного ввода и работы с датами.

### `home_tasks/`

Настройки Django-проекта, корневые маршруты и обработчик `handler404`.

### `homepage/`, `chores/`, `categories/`

Веб-приложения: главная страница, список и карточка дел, список
и карточка категорий. HTML собирается функцией `page()` в
`homepage/views.py` (общий каркас и Bootstrap 5.3). Модели Django
для предметной области на этом этапе не используются.

### `tests/`

Автоматизированные тесты объектов, методов и функций коллекций.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`. При загрузке они
преобразуются в коллекции `list[User]`, `list[Category]`, `list[Chore]`.
Даты записываются в формате `ГГГГ-ММ-ДД`, а вводятся и выводятся
в формате `ДД.ММ.ГГГГ`.

`data/users.json`:

```json
[
  { "id": 1, "name": "Алексей", "email": "alexey@home.local" }
]
```

`data/categories.json`:

```json
[
  { "id": 1, "name": "Кухня" }
]
```

`data/chores.json`:

```json
[
  {
    "id": 1,
    "title": "Помыть посуду",
    "user_id": 1,
    "category_id": 1,
    "priority": 3,
    "due_date": "2026-09-18",
    "status": "Запланировано"
  }
]
```

## Требования

- Python 3.10 и выше;
- Django 5.2;
- pytest;
- flake8.

Установка зависимостей:

```
pip install -r requirements.txt
```

## Запуск консоли

```
python main.py
```

## Запуск веб-интерфейса

Подготовить служебные таблицы Django и проверить проект:

```
python manage.py migrate
python manage.py check
```

Запустить сервер разработки:

```
python manage.py runserver
```

Страницы:

- `/` — главная;
- `/chores/` — список дел;
- `/chores/<id>/` — карточка дела;
- `/categories/` — список категорий;
- `/categories/<id>/` — категория и её дела.

Несуществующие адреса и неизвестные идентификаторы возвращают
страницу «не найдено» с кодом 404. Создание, редактирование
и удаление через веб на этом этапе не реализованы: данные
по-прежнему меняются в консоли и хранятся в JSON.

## Запуск тестов

```
pytest -v
```

Тесты проверяют создание объектов `User`, `Category`, `Status` и `Chore`,
методы классов, связь дела с пользователем и категорией, а также
сохранённую функциональность ПР2.

## Проверка качества кода

```
flake8 . --extend-exclude=venv
```

## Преемственность этапов

- ПР1 — карточка одного дела на простых типах и функциях;
- ПР2 — коллекции словарей, модули, JSON и меню;
- ПР3 — сущности представлены классами, коллекции содержат объекты,
  дело хранит ссылки на `User` и `Category`;
- ПР5 — веб-слой Django: маршруты, HTML-страницы и вывод объектов
  из JSON. Консоль, классы и тесты ПР3 сохранены.

Функции `get_chore_status()`, `get_days_left()`,
`get_deadline_message()` и `get_priority_label()` сохранены
в модуле `models/chores.py` и используются вместе с методами объекта
`Chore` при выводе карточки дела.
